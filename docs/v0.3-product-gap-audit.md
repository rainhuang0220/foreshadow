## 3. Auth — research and choice

Sources: GitHub Docs *Authorizing OAuth apps*, *Differences between GitHub Apps and OAuth apps*, *Authenticating with a GitHub App on behalf of a user*, *Generating a user access token for a GitHub App*; oauth2-proxy 7.15 GitHub provider + cookie docs; Cloudflare Tunnel setup (2026-09-02); Starlette SessionMiddleware is cookie-signed state, not a revocable server session.

### Comparison (single-operator Foreshadow)

| Option | Identity | Persistence | HTTPS | Write later | Fit |
|---|---|---|---|---|---|
| **GitHub OAuth App, identity-only** | `login` from `GET /user` | We own SQLite sessions | Callback must be https except loopback | Do **not** keep the token | **Login P0** |
| GitHub App user-to-server | Same web flow, no scopes; tokens expire + refresh | Same | Same | Installation token is the write path | **Login+write long-term** |
| oauth2-proxy GitHub | Header identity | Cookie default 168h, Secure default on | Needs TLS | Wrong layer | Overkill; fights anonymous Board |
| Cloudflare Access | IdP in front of everything | CF session | TLS included | None | Breaks public viewer |
| Password (current) | Foreshadow-invented | 14d, no Secure, no rotation | HTTP cookie on a public IP | None | Unqualified for daily personal tool |
| Browser plugin | — | — | — | — | Rejected |

**Decision: GitHub OAuth web flow for identity. Foreshadow server-side session for persistence. GitHub write tokens are a different credential, later.**

Flow:

```
anonymous Board
→ operator action or Login
→ GitHub OAuth (no repo scopes)
→ allowlist github_login
→ 30-day hashed session, HttpOnly, SameSite=Lax, Secure iff HTTPS
→ header shows github login + logout
```

- Allowlist: `FORESHADOW_OPERATORS` env/config (comma-separated). Never hardcode `rainhuang0220` in source.
- Non-allowlisted GitHub users: refused (“不是授权操作者”). Anonymous read stays.
- Do not persist the GitHub access token after `GET /user`.
- Keep password login as a **local/dev fallback** so the existing `rain` row is not stranded before OAuth is configured. Public UX is GitHub-first.
- Session: 30 days; rotate on login; revoke on logout; Origin check stays (CSRF); OAuth `state` in `oauth_states`.
- Cookie `Secure` only when the request is HTTPS (`X-Forwarded-Proto` from loopback nginx). On public HTTP, Secure cookies would never be stored — that is why HTTPS is not optional for this login.

GitHub will not accept `http://175.24.134.228:666/api/auth/github/callback` as a production redirect. Loopback HTTP is the documented exception.

### HTTPS

Same VM already terminates TLS for `plainlist.space`. Recommended production URL:

```text
https://foreshadow.plainlist.space/
```

Requires: DNSPod A record `foreshadow.plainlist.space` → `175.24.134.228`, certbot for that name, new nginx 80/443 vhost → `127.0.0.1:8765`. Keep `:666` as a temporary HTTP alias (no Secure cookie, no OAuth callback).

Not chosen now: Cloudflare Tunnel (needs a Cloudflare-zoned domain; extra daemon); putting Foreshadow under `plainlist.space/api/` (collides with the other product).

If the A record cannot be added in this session, OAuth is still fully tested against `http://127.0.0.1/` and the vhost files ship in `contrib/`.

## 5. Entry Strategy

`pipeline/strategy.py` already picks an EntryPath enum (default Issue, not PR) from hydrate samples. It does **not**:

- read CONTRIBUTING / templates / CLA / DCO
- measure maintainer response or newcomer merge rate honestly
- rank a real Issue vs repro vs docs vs “file issue first”
- return Plan A + B + C with confidence and evidence IDs
- cache analysis

v0.3 Entry Strategy is a **deterministic extractor + optional LLM interpretation**. LLM cannot invent issue numbers or star deltas. Every recommended issue/PR must be a real GitHub id from GET/GraphQL.

Cost funnel: 120 discover → ~24 observe → ~20 shortlist → ≤5 deep entry analyses → 1–3 executions.

## 6. Coding backend

| Backend | License | Self-host | Sandbox | issue→patch | Integrate |
|---|---|---|---|---|---|
| **OpenHands Software Agent SDK** | MIT | yes | Docker/K8s Agent Server or local (unsafe) | skills: `github-issue-to-pr`, `iterate`, `qa-changes` | Real library, heavier |
| **mini-SWE-agent** | MIT | yes | docker/podman/singularity/bubblewrap | bash-only agent, SWE-bench >74% | Thin, easy adapter |
| SWE-agent | MIT | yes | SWE-ReX (MIT) | richer tools | Heavier than mini |
| Native Foreshadow | MIT | yes | Docker first | clone + tests + patch | We own QA/approval |
| Copilot coding agent | proprietary | no | GitHub-hosted | yes | Not self-host |

**Decision:** Foreshadow is the orchestrator. `ContributionExecutor` protocol with backends `native` (P0 of executor), `mini_swe_agent` (first mature external), `openhands` (adapter, optional extra). Do not vendor OpenHands. Do not put GitHub write tokens in the sandbox.

PoC rule: real third-party repo, local patch, **no push, no PR**.

## 7. Security architecture

```
[Browser] --HTTPS--> nginx --> Board (identity session only)
                                 |
                                 +-- GitHub OAuth (login, token discarded)
                                 +-- GITHUB_TOKEN (read-only PAT, host env, never in sandbox)
                                 +-- Approval Service (future GitHub App installation token)
[Sandbox Docker]  no network to api.github.com with write creds
                  no host HOME, no docker.sock, no git hooks
```

Remote write stays refused until a later dogfood of Contribution Ready. UI may show `[Approve & Create Draft PR]` disabled.
